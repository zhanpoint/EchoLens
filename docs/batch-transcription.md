# 博主语料采集

入口：主页侧栏「博主语料采集」，或直接打开 `/batch`。

页面采用居中的单栏布局：获取与筛选、任务进度位于视频列表上方。列表工具栏在搜索框右侧依次放置转录按钮、导出格式、导出方式和导出按钮，窄屏自动换行。进度与恢复说明默认收起在信息图标内，逐条显示；有多个任务时通过「历史任务」入口切换。作品列表与任务明细限制滚动高度，避免大量作品把操作推到很远的位置。

## 使用

1. 登录，选择抖音或哔哩哔哩。输入用户主页链接；Bilibili 支持 UID，抖音支持 sec_uid 和可解析的主页分享短链接。
2. 默认获取全部视频，也可组合设置发布时间范围、标题关键词和视频标签；标签支持任一或全部匹配。日期包含北京时间首尾当天。可选择匹配结果中最新或最早的 N 个视频（1–5000）。点击「获取」自动遍历分页；每页结果、游标和筛选条件保存到当前 EchoLens 用户的浏览器 IndexedDB，中断或刷新后可继续。
3. 在已获取列表中搜索、勾选视频，或全选筛选结果，创建批量任务。语音识别统一使用 E1：准备后的音频时长不超过 5 分钟时使用 `qwen-audio-3.1-asr-flash`，更长或时长未知时使用 `qwen-audio-3.1-asr-flash-filetrans`；Bilibili 分 P 按各分 P 的音频时长分别选择。转录后处理与 AI 总结默认使用 `deepseek-v4.1-flash`。单批最多 5000 个视频，重复视频会去重。作品列表和任务详情均支持首页、上一页、下一页、末页快捷图标。
4. 查看每个视频的进度、暂停或继续任务。有失败或未完成项时，任务进度右侧显示「重试」按钮：重新排队失败和已取消项，恢复暂停批次，保留等待项与正在执行项的租约；中断项仍通过原租约过期机制接管。也可点击某个失败作品旁的「重试」仅重试该作品。重试保留服务商任务与分 P 检查点，已成功的视频不重新处理；按钮显示处理状态，避免重复操作。
   也可取消转录：终止未完成项，已完成文件保留。取消后不会自动恢复，显式点击「重试」可恢复未完成项。
5. 默认按选择顺序合并导出 Markdown，也支持 UTF-8 TXT、JSON。文件包含平台、作品 ID、标题、来源链接、发布时间、时长、可用标签与转录正文。任务中每个已完成作品可单独下载；支持目录选择的浏览器还可选择目录，将每个作品直接保存为单独文件，不压缩打包。目录保存可中途停止，已完成文件保留；重新导出覆盖同名文件。

获取范围使用 32px 高的紧凑控件，日期通过主题日历选择，数量通过加减按钮或键盘上下键调整。范围规则与平台说明默认收起在信息图标中，点击后逐条显示。文件格式显示为 Markdown、纯文本、JSON，不附带扩展名括号；格式与导出方式下拉框宽度分别为 112px、144px。

筛选规则与表单参数解析集中在 `src/lib/batch/video-filters.ts`，先按时间、关键词、标签筛选，再去重、按发布时间排序和截取数量。同一发布时间按作品 ID 固定排序，未知发布时间排在最后。抖音作品列表可能有置顶视频，不能把返回顺序当成发布时间顺序，也不能因某页筛选后为空而结束分页。最新 / 最早 N 个需要扫描全部分页才能确认完整排名；期间保留候选和恢复游标，排名完成前不允许把暂定候选提交转录。已经完整获取全部抖音作品后，修改时间、标题、标签或数量直接在本地筛选，保留原始列表并分别显示已获取数与匹配数。之前获取的是受限范围、扫描尚未完成，或 Bilibili 缺少新筛选所需的完整标签时，保留原列表并提示点击「获取」应用新条件；应用前禁用转录选择，避免把不同条件的分页结果混合。

关键词、标题搜索和标签统一使用 Unicode NFKC 与英文小写归一化，兼容全角 `＃` 与全角英文；标签去重并固定顺序，逗号、换行和 `#` 可分隔多个标签。数量仅接受 1–5000 的十进制整数，“全部作品”不使用数量框的旧值；无效数量或日期范围立即提示并禁止获取和选择转录。当前有效筛选以单独的小型缓存记录保存，刷新后恢复，不为每次修改重写整个作品列表。

抖音标签根据参考源码 `core/downloader_base.py::_extract_tags` 读取 `text_extra`、`cha_list` 和描述中的话题。匹配器统一合并独立标签与标题中的 `#话题`，旧浏览器缓存没有标签字段时仍可匹配标题话题。Bilibili 投稿列表不提供完整标签，仅在启用标签筛选时，对已通过日期和标题筛选的作品查询官方标签接口；无标签筛选时不发起额外标签请求。标签匹配为去除 `#`、Unicode 归一化及忽略英文大小写后的完整匹配，不把 `AI工具` 误当成 `AI`。

抖音获取的是当前账号可见的公开视频，需已验证的访问凭证，沿用现有账号服务开关和邀请授权。图文作品不列入视频列表。Bilibili 获取用户空间公开投稿，多分 P 视频会转录全部分 P，各分 P 的文字合并到该视频对应的文件。私密、删除、地区限制或平台禁止访问的内容无法由客户端保证获取。

## 恢复与暂停语义

- 批量任务和每项结果存入 PostgreSQL，后台执行不依赖页面保持打开。浏览器缓存只负责作品列表，不能替代任务存储。
- 暂停停止领取新任务；当前已领取的视频继续完成、保存。恢复后处理剩余等待项。
- 取消在同一事务中设置批次终态、取消等待及处理中项目并清除租约，阻止新派发及旧执行器回写。执行器在下一次检查点或租约续约时停止；已接受的服务商任务可能继续执行、计费，取消不意味着撤销服务商任务。
- 任务详情根据租约期限区分活跃处理与中断待恢复项，避免服务退出后长期显示虚假的处理中动画。
- 进度按视频、Bilibili 分 P、ASR 任务 ID 和成功结果持久化。已经完成的分 P 跳过；服务商已接受的 ASR 任务继续轮询，不因刷新页面或手动重试网络失败项而重新提交。
- 工作租约为 120 秒，每 30 秒续约。进程退出后，其他执行器在租约过期时接管；提交结果使用租约令牌约束，旧执行器不能覆盖新执行器的结果。
- 网络失败使用有上限的退避重试，每项最多 5 次执行后等待手动重试。额度不足、转录配置缺失、凭据失效或平台冷却会暂停批次。
- 平台限流、完成的空响应、浏览器会话不可用以及抖音凭证缺失时暂停当前批次；当前条目保持“等待继续”，保留检查点，不增加重试次数。恢复后无需再把该条目按失败重试。
- ASR 成功状态和结果一起保存，即使进程在写入批量结果前退出，也能复用已保存的服务商结果。并发轮询的终态提交也会复用已落库的成功结果。
- 短音频使用同步识别接口，收到结果后先保存原始文字，再执行后处理；后处理失败时恢复已有文字，不重复识别。同步提交没有可查询的服务商任务 ID，提交结果不明时提示核对服务商记录，禁止自动重复提交。
- 如果服务商可能已接受提交，但连接中断且没有返回任务 ID，系统会标记该项失败并提示先核对服务商记录。没有服务商幂等提交契约时，不能保证这个窗口内的重试绝不重复计费。
- 恢复是任务级和分 P 级的检查点恢复。尚未完成的音频准备可能重新执行；已经上传的原声音频复用 OSS 缓存，不声称所有上游媒体连接都支持字节续传。

## 运行配置

使用现有 PostgreSQL、OSS 和 DashScope 配置，不增加 Redis 服务。首次启动自动执行事务化的 `transcript-schema-v6-durable-batches` 迁移，保留旧任务及历史数据，增加批量表和 ASR 结果列。`transcript-schema-v7-qwen-audio-31` 一次性将旧模型配置迁移为新的 E1 和后处理、总结默认值，移除 E2 / E3 配置；保留翻译模型及凭据，后续用户修改不会被重复迁移覆盖。

抖音作品接口现由网页 SDK 会话发送请求，运行时需要浏览器。Windows 默认复用已安装的 Edge；其他本机环境运行 `npx playwright install chromium`。自定义浏览器可设置 `DOUYIN_BROWSER_EXECUTABLE`。Dockerfile 已加入 Chromium 和系统依赖安装，浏览器文件通过 `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright` 供应用用户读取。会话仅存在内存，不保存浏览器登录资料到磁盘；同一凭证复用上下文，不同凭证隔离，最多保留 4 个会话，空闲 2 分钟关闭。

`BATCH_TRANSCRIBE_CONCURRENCY=2` 控制每个 Node 进程的并行视频数，接受 1–8，未配置或值无效时使用 2。多实例仍通过 PostgreSQL `FOR UPDATE SKIP LOCKED` 和租约协调；总并行数是各实例并行数之和。

后台执行器通过 Next.js `instrumentation.register()` 启动；运行环境应为持续运行的 Node 服务，例如当前的 `npm run dev`、`next start` 或 Docker standalone。不能把普通短生命周期的 serverless 请求当作持续后台执行服务。使用自定义 API Key 时优先使用该 Key；没有自定义 Key 时使用平台额度，遵循现有原子额度预留机制。

执行器启动会替换旧定时器回调，同时复用在途计数与派发锁。这样开发热更新后创建或重试任务会使用当前模块，不会因全局单例提前返回而继续执行旧模型配置读取逻辑；已有执行不重复派发。任务控制接口为 `PATCH /api/batch/{id}`，批量重试发送 `{ "action": "retry" }`，逐项重试增加 `itemId`。目标必须属于当前用户的当前批次且状态为失败或已取消，其他条目和已完成结果保留。没有失败项的暂停批次也可重试恢复，活跃处理中条目的租约不变，避免重复派发。

导出使用分批数据库读取和流式 Markdown / TXT / JSON 输出；按读取开始时的完成时间截取结果。目录保存每次读取最多 50 条 JSON 记录，复用首个响应的时间快照并按作品序号继续分页，每条记录直接写入对应文件，避免整批缓存在内存或为每个文件重复请求。文件写入成功后关闭流，失败或取消时中止未完成写入。文件名包含序号与作品 ID，同名视频不会互相覆盖。列表每页显示 30 个作品，任务详情每页读取 50 项，任务面板显示最近 30 个批次。

导出接口：`GET /api/batch/{id}/export?format=md|txt|json`；可选 `position` 为批次中的零基序号，仅导出该已完成作品。目录保存使用 `after` 序号游标（初始 -1），每页最多 50 项；后续请求的 `asOf` 复用首个响应的 `x-export-as-of`。所有查询按任务所有者隔离，未知格式、压缩格式及无效序号返回 400，不存在的作品返回 404，尚未完成的作品返回 409。浏览器目录选择复用项目现有下载目录功能；不支持目录选择时仍可合并下载或逐作品下载。
